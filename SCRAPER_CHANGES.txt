✅ CHANGES COMPLETED:

1. REMOVED Direct TSDB Storage
   ❌ No longer uses local TSDB instance
   ❌ Removed -data, -cache, -memory flags
   ✅ Now sends metrics via HTTP API

2. ADDED HTTP API Communication
   ✅ Sends metrics to Krill server using /api/v1/write endpoint
   ✅ JSON payload: {"metric":"name","value":123.45,"time":1234567890}
   ✅ Automatic retry logic built into HTTP client

3. SIMPLIFIED Parameters
   OLD: -config <file> -data <dir> -cache <duration> -memory -stats <interval>
   NEW: -config <file> -server <url> -stats <interval>

4. UPDATED Architecture
   
   BEFORE:
   ┌──────────┐    ┌──────────┐    ┌──────┐
   │ Exporter │───▶│ Scraper  │───▶│ TSDB │
   └──────────┘    │ (local)  │    └──────┘
                   └──────────┘
   
   AFTER:
   ┌──────────┐    ┌──────────┐    ┌────────┐    ┌──────┐
   │ Exporter │───▶│ Scraper  │───▶│ Server │───▶│ TSDB │
   └──────────┘    └──────────┘    │  API   │    └──────┘
                                    └────────┘

📋 USAGE EXAMPLES:

# 1. Start Krill server
./krill-server

# 2. Run scraper (connects to local server)
./krill-scraper -config scraper.yaml

# 3. Connect to remote server
./krill-scraper -config scraper.yaml -server http://192.168.1.100:9090

# 4. With custom statistics interval
./krill-scraper -config scraper.yaml -server http://localhost:9090 -stats 30s

🎯 BENEFITS:

✅ Centralized Storage
   - Multiple scrapers can send to one server
   - Server handles all data persistence
   - Easier to scale horizontally

✅ Separation of Concerns
   - Scraper: collect metrics
   - Server: store and query metrics
   - Clear responsibility boundaries

✅ Simpler Deployment
   - No storage configuration in scraper
   - Just point to server URL
   - Easier to configure and maintain

✅ Network Flexibility
   - Scraper can run anywhere
   - Send metrics over network
   - Support distributed deployments
